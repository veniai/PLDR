# PLDR 调研记录

调研日期：2026-08-26

## 核心判断

PLDR 的长期资产应由来源、采集任务、文档、网页版本、事件、实体、主张、证据、关系、研判、报告和人工反馈构成。模型能够替换，原始证据和历史对象不能丢失。

当前概率最高的实现路径，是从干净仓库起步，自建最小领域对象。短期吸收 World Monitor 的态势展示与来源健康思路，吸收 BettaFish 的问题驱动分析和报告流程，吸收 Palantir 的对象化、动作和追溯方法。采集优先使用 RSS、普通 HTTP、GDELT 和必要时的 Crawl4AI。后续根据真实瓶颈再接入 OpenAleph、ArchiveBox、MiroFlow、全文搜索或图数据库。

## 已确认的项目能力与 PLDR 使用判断

### Palantir Foundry 与 AIP Analyst

已确认能力：以对象、属性、关系、动作和函数组织业务世界，分析过程可以通过 trace graph 追溯。

PLDR 判断：重点学习对象化、分析轨迹、动作入口和人工反馈，不复制闭源产品。P0 只实现 Event、Entity、Claim、Evidence 的最小对象链和可展开证据。

### World Monitor

已确认能力：全球新闻聚合、地图与时间线、多信号关联、来源健康和情报缺口提示。项目强调多源印证、失败降级、缓存和明确展示看不见的数据。

PLDR 判断：作为 P0 的视觉和运维参考。只学习布局、信号分层、来源状态和证据缺口表达，不复制 AGPL 代码。

### BettaFish

已确认能力：MindSpider 采集，Query、Media、Insight、Forum、Report 多模块协作，支持 OpenAI 兼容模型和 HTML、PDF、Markdown 报告。

PLDR 判断：学习问题驱动分析、并行研究、报告中间表示和报告生成流程。仓库为 GPL-2.0，长期核心不直接基于其代码。

### MiroFish

已确认能力：从种子材料构建图和角色，进行群体仿真并由 ReportAgent 生成预测报告。

PLDR 判断：放入 P4 研究。证据对象、评估和回测没有稳定前，不引入群体模拟和预测分数。

### MiroFlow 与 MiroThinker

已确认能力：MiroFlow 是模块化多步研究 Agent 框架，支持搜索、代码、文件、视觉、分层子 Agent、并发和故障恢复。MiroThinker 面向长链研究和工具交互。

PLDR 判断：P2 以后作为可替换的深度研究服务候选。它们不承担持续采集、证据保存和核心对象管理。P0 仅保留统一模型任务接口。

### Crawl4AI

已确认能力：Playwright 动态页面、会话、代理、Cookie、正文 Markdown、结构化抽取、截图、深度爬取和 Docker API。

PLDR 判断：P1 用于少量动态网页。P0 优先稳定 RSS 和普通网页，避免浏览器运行时抢占时间。

### RSSHub

已确认能力：大量站点路由，可以把缺少 RSS 的内容源转换为订阅源。

PLDR 判断：P2 作为独立服务或 Connector 接入。路由容易随目标站点变化，不能替代自己的来源目录和健康监控。项目为 AGPL。

### OpenCTI

已确认能力：STIX2 结构、原始来源、first seen、last seen、置信度、关系推导、连接器和导入导出。

PLDR 判断：用于来源、置信度、关系和时间语义设计参考。其网络威胁领域模型和部署规模不适合一般开源情报 MVP。

### OpenAleph 与 FollowTheMoney

已确认能力：OpenAleph 支持大量文档和结构化数据索引、实体交叉检索与协作调查。FollowTheMoney 提供人物、公司、资产、支付和案件等调查实体模型。

PLDR 判断：P3 可作为独立调查资料库或实体规范参考。P0 和 P1 不引入其完整 Elasticsearch、PostgreSQL、Redis 栈。

### ArchiveBox 与 changedetection.io

已确认能力：ArchiveBox 能以 HTML、PDF、PNG、WARC、JSON 等标准格式保存网页。changedetection.io 能监控网页和 PDF 变化，并支持选择器、浏览器步骤和通知。

PLDR 判断：P2 按需要接入。P0 先保存正文、元数据、内容哈希和公开原文链接，演示数据同时保留本地证据片段。

### LiteLLM 与 Langfuse

已确认能力：LiteLLM 提供多模型网关、路由、成本和日志。Langfuse 提供调用追踪、提示词版本、数据集和评估。

PLDR 判断：P0 自建几十行的 OpenAI 兼容任务接口，避免引入重服务。P2 出现多供应商、预算和评估需求后再接入。

### NewsNow

已确认能力：实时热点新闻聚合、轻量 UI、缓存、来源适配和 MCP 接口。

PLDR 判断：适合参考 P0 的信息密度、加载速度和来源适配组织方式。PLDR 必须补上事件聚合、证据、来源独立性和研判对象。

## 关键分歧

一条路线把 P0 做成静态大屏，能够很快展示，但后续代码大概率废弃。

另一条路线从完整采集平台起步，工程更真实，但 72 小时内很难呈现完整产品形态。

当前选择是薄后端的真实纵向切片。RSS 和普通网页真实进入，事件和证据对象真实存在，复杂来源与大规模运行使用缓存和预计算降级。这样能够演示，也能继续演化到 P1。

## 信息缺口

1. 首个公开专题尚未冻结。
2. 真实用户最看重的是态势展示、专题跟踪、调查检索还是自动报告，仍需通过演示反馈验证。
3. 首批来源的语言、地区、服务条款和更新频率尚未形成专题包。
4. 对外展示是否要求地图主视图尚未确认。
