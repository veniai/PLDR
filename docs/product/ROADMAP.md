# PLDR 路线图

更新时间：2026-08-30

## 顺序与产品基线

阶段严格按 **P0/P0.2/P0.3（已完成）→ P1（关键词发现切片已完成，可靠采集继续）→ P2 → P3 → P4** 推进。当前下一优先级仍是 P1；P2-P4 不作为并行产品阶段启动。

所有阶段沿用证据优先对象链：来源—文档—快照—主张—证据—研判。Event 和 Entity 组织关系，AI 只产生可检查的候选结果；正式档案和报告只读取已确认对象。

输入路线同样固定：确定网页、可靠 API、粘贴文本、本地文件与关键词发现属于同一个专题的并列入口。已知来源走直接/持续采集，不足时用搜索补充未知 URL；搜索不是其他输入的上游，也不把标题和摘要升级成证据。当前通用 API 可靠采集尚未实现，仍由 P1 持有。

## P0/P0.2，已完成的可运行纵向切片

**唯一目标：** 证明从固定专题、公开材料、事件和证据到结构化研判及 HTML 简报的产品闭环，并把它收敛为分析员可操作的工作台。

**已实现边界：** 16 个来源、48 篇文档、8 个事件、24 条主张、56 条证据；网页/RSS 导入、来源独立组、快照高亮、筛选联动和事件简报。P0.2 已在提交 `7d3f71a` 合入 `master`。

**不包含：** 正式采集箱、粘贴文本/本地文件入口、候选对象审核、确认入档。

**退出证据：** `./scripts/test-p0.sh` 通过；三分钟演示可走完专题、事件、证据和报告；GitHub Actions 对提交 `7d3f71a` 的运行结果已核实为成功。

## P0.3，待处理采集箱与人工确认入档（已完成）

**唯一目标：** 让网页、粘贴文本和本地文件以同一套受控流程进入待处理采集箱，经 AI 生成候选事件、实体、主张和证据，再由分析员新建、合并、修改或驳回；只有确认结果进入正式事件档案和可追溯报告。

**暂不实现：** 定时/连续采集、来源规模扩张、网页版本调度、多人权限审批、通用图数据库、跨媒体传播链、自动事实裁决。AI 不得直接写正式档案。

**退出/验收条件：**

1. 网页、粘贴文本、本地文件三条路径都能产生带输入类型、处理状态和错误信息的采集箱条目。
2. 每条成功解析的材料保留可回到来源或上传材料的 Document/Snapshot；失败项停留在采集箱并可重试，不产生正式对象。
3. AI 输出只以候选事件、实体、主张和证据呈现；候选证据必须能定位到对应快照原文，否则不能确认。
4. 分析员能对候选执行新建、合并到既有对象、修改后确认或驳回，并能预览即将写入的关系。
5. 确认动作原子地生成或关联正式对象；事件档案和报告可沿证据回到快照、文档和来源，并保留人工处置记录。
6. 未处理、失败、撤销和驳回均不改变正式事件档案、统计或报告；重复确认不会产生重复正式对象。

逐路径验收脚本和状态约束见 `P0.3-INGESTION-INBOX.md`。

**退出证据：** 当前工作区的 `./scripts/test-p0.sh` 通过；验收覆盖三类输入、候选隔离、证据定位、四种处置、原子性、幂等、负向不污染、报告回链、既有 P0/P0.2 能力、Python 编译和前端 JavaScript 语法，并完成桌面与窄屏浏览器走查。

## P1 第一切片，外部关键词发现（已完成）

**唯一目标：** 在 P0.3 受控采集箱之上，让分析员在具体专题中通过现成真实检索后端按关键词发现新闻和一般公开网页，选择结果后异步逐条抓取原始页面，并沿用候选、证据定位和人工确认闭环。

**已实现边界：** Brave Search API REST v1 默认适配、SearXNG 2026.8.22 可配置适配、新闻/一般网页范围、自动/手动语言、结果规范化；查询历史按专题持久化并可重开，真实分页跨页去重，单查询最多加载 100 条，可全选本页/已加载结果并一次选择最多 100 条。上游总数未知时保持未知。选择后返回逐条异步任务，结构化错误区分可恢复超时/限流与不可直接重试的 DNS/SSRF 策略拒绝。查询/渠道/结果/材料追踪、失败隔离、重试和幂等保持不变。检索结果不是正式 Source 或 Evidence。

**专题闭环：** “今天”按注意力排序展示待审、处理中、失败和正式事件；当前研判把来源可靠性、独立印证、证据完整性和人工研判分开说明，不生成虚假的综合知情度。审核默认限定本专题，跨专题复用需显式授权；语义预览显示即将写入的对象/关系，确认后进入正式事件并可继续下一条任务，专题报告只读取确认对象。

**退出证据：** 原始切片已有 `./scripts/test-p0.sh` 和 2026-08-28 浏览器闭环证据；2026-08-30 工作区新增专题隔离/历史、多页/批量、未知总数、结构化错误、旧库迁移、语义审核和确认导航的自动契约。新提交候选必须重新执行项目原生测试、Compose 配置、Diff 检查及桌面/窄屏浏览器流程，不能沿用旧浏览器记录冒充新界面验收。

## P1，可靠采集 MVP（继续推进）

**唯一目标：** 在 P0.3 的受控入档闭环之上，证明小规模真实来源可以持续、可恢复地运行。

**范围：** 30 至 50 个来源；固定网页、RSS、通用 API 与必要的受控浏览器来源；采集任务调度、重试和来源健康；网页版本历史；PostgreSQL/PostGIS 迁移；模型调用日志与成本；P0.3 已确认对象的增量更新。

**已实现的纵向切片：** 固定公共 HTTP(S) 网页可以配置周期并进入持久队列；单 worker 支持手动、到期、失败重试和过期租约恢复；首次/未变/变化/失败明确分层，变化形成不可变待审版本和确定性 Diff；人工确认同 URL 新版本时复用正式 Document、追加 Snapshot，并保证新旧 Evidence 分别固定对应快照。RSS/Atom 可按目标内条目指纹持续发现新条目，重复项不入箱，私网/无效条目 fail-closed，条目标题和摘要快照仍走 P0.3 人工确认。工作台已提供来源健康、运行、版本、Diff、发现条目和进入待审的真实操作入口。完整契约见 `P1-RELIABLE-COLLECTION-SLICE.md`。

**仍待完成：** API/浏览器类可靠来源、RSS 条目原文追抓、真实来源包扩到 30–50 个、连续 72 小时运行证据、PostgreSQL/PostGIS 和正式迁移、模型调用用量/成本台账、增量更新策略与最终验收报告。当前切片通过不等于 P1 阶段退出。

**暂不实现：** 大规模多语言运营、团队审批、外部平台 API/MCP、跨媒体转载链和预测能力；不把 P0.3 的人工确认改成无人值守发布。

**退出/验收条件：** 选定真实来源连续运行 72 小时；每个采集任务可追踪成功、失败和重试；同一网页变化形成可比较版本；抽样确认的正式主张全部回链到对应快照；进程重启后队列不丢失且不重复入档；验收报告公开样本量、成功率、失败分类和成本，而不是只给主观结论。

## 参考项目使用原则

Palantir、World Monitor、OpenAleph、OpenCTI、changedetection.io、NewsNow 等项目继续作为对象动作、专题检索、来源健康、可靠性/置信度分离、变化历史和高密度列表的模式参考。PLDR 以自身证据链和当前阶段退出条件决定是否吸收，不把功能清单机械拼接到一起。当前前后端为独立实现，不复制 AGPL/GPL 受限代码；任何未来代码复用、独立服务接入或对外部署都要单独固定版本并复核许可证、版权和数据条款。

## P2，分析团队试点

**唯一目标：** 证明一个分析团队能在真实专题中持续使用并交付经过审核的报告。

**范围：** 100 至 300 个来源、多语言归一、提醒、实体别名、任务分派、报告审核、评估集和成本看板；人工拆分/合并扩展到已入档对象并保留变更历史。

**暂不实现：** 企业级细粒度权限、公开平台接口、复杂插件生态、自动事实裁决、预测和情景推演。

**退出/验收条件：** 至少一个真实专题完成不少于两周的团队试点；从提醒到分派、确认、复核、报告发布全程可追踪；双人复核样本能计算候选采纳/修改/驳回率和一致性；对象拆分合并后历史引用仍可解析；试点用户依据预先定义的任务清单完成操作且关键失败有记录和处置。

## P3，治理与平台 v1

**唯一目标：** 把已验证的工作流变成可治理、可集成、可稳定运维的平台。

**范围：** 来源治理、版本化正式对象、角色权限与审批、不可抵赖审计、报告模板、稳定 REST API、MCP、备份恢复、服务级运行指标，以及在部署/分发前完成长期许可证路径决策并记录适用边界。

**暂不实现：** 传播预测、自动决策、无人工控制的外部动作和未经评估的跨域模型能力。

**退出/验收条件：** 权限矩阵的允许/拒绝用例全部通过；对象和报告修改均能定位操作者、时间和前后版本；API/MCP 契约测试通过；备份恢复演练可重建对象链及引用；预设运行周期内服务指标达到事先声明目标，且安全/审计检查无阻断项。

## P4，证据化差异能力

**唯一目标：** 在稳定证据链与治理基础上，验证确实优于基础检索/聚合的分析能力。

**范围：** 跨语言早期信号、传播时滞、冲突主张、跨媒体转载链、来源独立性、跨信号关联、竞争假设和受控情景推演。

**暂不实现：** 无基线的“智能评分”、把预测包装成事实、自动对外决策或无法回溯输入证据的生成内容。

**退出/验收条件：** 每项能力在冻结评估集上与明确基线比较，报告精确率/召回率或对应任务指标、误差和成本；输出能够回到输入证据并区分事实、推断与情景；分析员盲评证明至少一项核心任务有可重复改进；未达到基线的能力不进入默认产品流程。
