# PLDR 开源情报工作台功能与性能指标要求

**版本：** P1 交付版 v1.0

**更新时间：** 2026-08-31

## 1. 一句话说清 PLDR

PLDR 帮助分析员围绕一个明确问题持续收集公开信息，把新材料整理成可核对的事件、人物、组织、地点、主张和证据，并输出中文的每日新增报告和专题总成果。

用户只需要说明三件事：

```text
我要查什么
我关心哪些关键词和网站
我手上已有哪些资料
```

PLDR 负责搜索、采集、保存原文、生成草稿、组织证据，并在人工确认后形成可交付成果。

![PLDR 总体结构](diagrams/pldr-overview.png)

## 2. 用户获得的结果

PLDR 输出两类成果。

### 2.1 每日新增报告

每日报告回答：

```text
今天新增了什么？
哪些来源发生了变化？
哪些材料等待核对？
哪些事件得到确认？
哪些信息仍需补充？
```

适用场景：

- 每天早间安全简报
- 突发事件跟踪
- 固定来源变化通报
- 待处理材料清单

### 2.2 专题总成果

总成果是一个持续沉淀的专题档案，回答：

```text
截至目前确认了哪些事件？
涉及哪些人物、组织和地点？
每条主张有什么证据？
不同来源之间有哪些分歧？
当前整体判断是什么？
还有哪些信息缺口？
```

总成果会随着新材料和人工确认持续更新。

| 入口 | 用户提供什么 | 系统做什么 | 当前状态 |
| --- | --- | --- | --- |

## 4. 前置配置

用户可以先给出最少信息，由系统生成建议配置，再由用户确认。

### 4.1 用户填写

```text
1. 我要查什么
   例：全球军事与安全动态

2. 关键词
   例：红海航运风险、无人机袭击、地区军演

3. 已知网站
   例：某公告页、某新闻 RSS、某研究页面

4. 已有资料
   例：PDF、文本、网页链接

5. 更新频率
   例：每小时、每 6 小时、每天
```

### 4.2 系统建议

系统根据用户目标自动生成初始建议：

| 建议项 | 说明 |
| --- | --- |
| 关键词扩展 | 从地区、事件类型、装备、组织、地点等角度补充搜索词 |
| 网站建议 | 从来源库中推荐适合该专题的公告、新闻、研究和监测页面 |
| 检查频率 | 根据来源更新特点建议每小时、每 6 小时或每天检查 |
| 重要程度 | 根据事件类型、影响范围、来源质量和时效给出优先级建议 |
| 报告结构 | 建议每日报告栏目和总成果栏目 |

用户可以确认、修改或补充建议。系统保存最终配置，并在后续运行中持续使用。

## 5. 系统处理流程

```text
入口材料
   ↓
公共网页抓取 / RSS 解析 / 文件解析
   ↓
保存原始材料与提取文本
   ↓
生成候选事件、实体、主张、证据
   ↓
分析员查看原文快照
   ↓
新建事件 / 合并已有事件 / 修改后确认 / 驳回
   ↓
形成正式专题成果
   ↓
持续监测新增与变化
```

## 6. 成果要素

![PLDR 证据链](diagrams/pldr-evidence-chain.png)

| 要素 | 面向用户的含义 | 示例 |
| --- | --- | --- |
| 专题 | 用户正在调查的问题 | 全球军事与安全动态 |
| 来源 | 材料来自哪个网站或资料 | 新闻社、公告页、研究机构 |
| 材料 | 一份具体网页、RSS 条目或文件 | 某篇报道、某份公告 |
| 快照 | 采集时的原文版本 | 保存页面正文、哈希和采集时间 |
| 事件 | 已确认发生的事情 | 某港口实施临时限制 |
| 实体 | 事件涉及的人物、组织、地点、装备 | 国家、机构、港口、船舶 |
| 主张 | 对事件的明确判断 | 限制从某日期开始生效 |
| 证据 | 支持主张的原文片段 | 新闻原文中的具体句子 |
| 研判 | 当前综合判断、假设、缺口和证伪条件 | 影响评估、替代解释、待核实问题 |
| 报告 | 可交付的中文成果 | 每日报告、专题总成果 |

## 11. P1 后续计划

P1 后续按以下顺序推进：

1. **专题来源包**
   - 建立首个真实专题的网站目录、关键词、更新频率和重要程度规则；
   - 系统根据用户目标生成建议配置，用户确认后启用。

2. **每日报告**
   - 汇总新增材料、新事件、网页变化、来源异常、待核对项和信息缺口；
   - 以中文交付，可按天留存版本。

3. **专题总成果**
   - 将已确认事件、实体、主张、证据、研判和报告组织成持续更新的总档案。

4. **RSS 原文追抓**
   - RSS 发现新条目后继续抓取原文页面；
   - 同时保留 feed 摘要与原文快照。

5. **结构化数据源**
   - 接入专题所需的公开结构化数据；
   - 与网页、关键词和资料进入同一审核和成果链路。

6. **规模与稳定性验证**
   - 扩展到 30–50 个真实来源；
   - 完成 72 小时连续运行报告；
   - 输出成功率、失败分类、恢复记录和成本统计。

7. **平台基础增强**
   - 迁移到 PostgreSQL/PostGIS；
   - 建立模型调用用量与成本台账；
   - 完成性能基准、备份恢复和增量更新策略。
