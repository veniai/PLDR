# PLDR 用户使用与验收说明

**适用版本：** P1 当前可测试版

**更新时间：** 2026-08-31

**在线地址：** `https://pldr.zhetengde.xyz`
**访问说明：** 网站使用受控测试账号；账号由管理员单独提供，本文档不保存密码。

## 1. PLDR 是干什么的

PLDR 用来围绕一个问题持续收集公开资料，把原文整理成可以核对的事件、主张和证据，最后形成中文专题成果和可留存报告。

普通用户只需要理解三部分：

```text
输入资料 → 系统处理、我来确认 → 查看专题成果
```

| 部分 | 用户要做什么 | 最后得到什么 |
| --- | --- | --- |
| 输入 | 说明要查什么；提供关键词、网页、文字或文件 | 一个已经开始收集资料的专题 |
| 处理 | 只处理需要确认或失败的内容 | 经人工确认的正式事件、主张和证据 |
| 成果 | 查看当前结论、变化、证据、时间线和报告 | 持续更新的专题成果与冻结报告 |

## 2. 五分钟走通一条完整流程

1. 登录网站，在“我的专题”点击 **创建专题**。
2. 填写专题名称；核心问题可直接采用系统建议。
3. 至少提供一种首批资料：关键词、网页/RSS、粘贴文本或本地文件。
4. 点击 **创建专题并开始**，进入专题后打开 **待处理**。
5. 对一条待确认资料选择 **采用**，查看“确认后将发生这些变化”，再点 **确认采用**。
6. 打开 **专题成果**，确认新增事件、主张和原文证据已经出现。
7. 点击 **生成当前报告**，检查报告只包含已确认内容，并能打开证据快照。

## 3. 第一部分：输入资料

### 3.1 一个窗口完成专题启动

在“我的专题”点击 **创建专题**。专题信息和首批资料在同一个窗口完成，不需要创建空专题后再重复添加。

![统一的专题输入入口](screenshots/input-01-unified-entry.png)

用户填写：

1. **专题名称**：用于识别专题，例如“海上无人作战”。
2. **核心问题**：系统根据名称给出建议，用户可以修改。
3. **事件时间**：可选，指事情发生的时间，不是新闻发布时间。
4. **更新方式**：默认持续关注，也可以选择一次性研究。

### 3.2 四种输入可以一起用

| 输入方式 | 用户怎么做 | 系统当前怎么处理 |
| --- | --- | --- |
| 关键词或问题 | 输入搜索词或一句问题 | 搜索公开资料，把选中的原网页送入专题处理队列 |
| 网页或 RSS | 每行填写一个公开 HTTP(S) 地址 | 保存网页或 RSS 材料，再由后台生成候选 |
| 粘贴文本 | 粘贴已经获得的原文 | 先保存原始文本和快照，再由后台生成候选 |
| 本地文件 | 选择 TXT、Markdown、HTML 或 PDF | 保存文件和可核验文本；单个文件最大 5 MiB |

![同时填写关键词、网址和已有资料](screenshots/input-02-filled-entry.png)

用户不需要选择来源语言。系统保留原文，用户看到的成果以中文为主；当前版本尚不承诺一次查询自动覆盖所有语言，也不把机器翻译冒充原始证据。

### 3.3 创建后立即进入专题

点击 **创建专题并开始** 后：

```text
专题先保存
→ 搜索和已有资料分别进入专题
→ 原文先保存
→ 后台继续整理候选
→ 用户可以立即离开创建窗口
```

外部模型慢或暂时失败时，已经保存的专题和资料不会被撤销；一条资料失败也不会拖垮整批。

![创建后直接进入专题](screenshots/input-03-topic-started.png)

## 4. 第二部分：系统处理和人工确认

### 4.1 “待处理”只保留真正要操作的事

专题里的内容分为三组：

| 分组 | 含义 | 用户要做什么 |
| --- | --- | --- |
| 需要你确认 | 原文已保存，系统已经整理出候选 | 打开后选择采用、修改后采用或不采用 |
| 需要处理 | 抓取或生成失败 | 看清原因后重试；不再需要的可以删除 |
| 系统正在处理 | 后台还在抓取或整理 | 无需操作，完成后会自动进入待确认 |

![只显示需要关注的处理队列](screenshots/process-01-attention-queue.png)

失败项必须直接说明：**在哪里失败、产生什么影响、下一步能做什么**。例如私网地址被安全规则阻止时，页面会明确显示安全拦截，而不是笼统提示“未知错误”。

### 4.2 用户只做三个决定

打开一条待确认资料后，先看固定原文，再看系统整理结果。

![原文与三个清晰决定](screenshots/process-02-review-decision.png)

| 决定 | 通俗含义 | 对正式成果的影响 |
| --- | --- | --- |
| 采用 | 整理结果基本正确 | 先展示影响预览，最后确认后写入正式成果 |
| 修改后采用 | 内容有用，但标题、时间、地点、主张或合并目标要调整 | 保存人工修改后的正式结果 |
| 不采用 | 与专题无关、重复或无法核实 | 保留材料和决定用于审计，正式成果不改变 |

如果系统发现同名正式事件，会建议合并；高级修改项默认收起，不干扰普通用户。

### 4.3 “采用”不是直接写入

第一次点击 **采用** 只生成语义预览，不写入正式档案。页面会明确列出：

- 保存哪个来源、材料和固定快照；
- 新建还是合并事件；
- 写入几条主张和证据；
- 证据原句能否定位到本次固定原文。

只有用户再次点击 **确认采用**，内容才进入正式成果。

![确认前展示准确影响](screenshots/process-03-confirm-impact.png)

### 4.4 人工确认边界

```text
搜索结果、网页摘要、AI 草稿 ≠ 正式成果

只有：固定原文 + 可定位证据 + 用户明确确认
才会进入专题成果和报告
```

因此，用户在“待处理”看到的候选不会提前出现在专题结论中；不采用、失败和仍在后台处理的内容也不会混入正式报告。

## 5. 第三部分：专题成果

### 5.1 进入专题先看结果

打开专题后默认进入 **专题成果**。这里不是数据库对象列表，而是直接回答用户最关心的问题：

1. **当前结论**：截至目前能确认什么。
2. **自上次报告以来**：新增、更新、疑点和待处理数量。
3. **关键发现与证据**：结论状态和原文依据。
4. **事件时间线**：已经确认的事件，不显示候选。
5. **关键参与方**：已经确认的人物、组织、地点或装备。
6. **未知与下一步**：明确说出仍不知道什么。
7. **报告与历史版本**：生成当前冻结报告，回看历史版本。

![专题成果首页](screenshots/output-01-topic-result.png)

完整长页效果：

![专题成果完整页面](screenshots/output-02-topic-result-full.png)

### 5.2 结论必须能回到证据

关键发现不会用一个不透明的“知情度总分”代替解释。每条主张单独显示“有支持、存在冲突、待核实、已确认或已反驳”，展开后可以看到：

- 精确原文片段；
- 来源和材料；
- 固定快照；
- 对该主张是支持、冲突还是背景。

### 5.3 持续专题与一次性专题

- **持续关注**：专题成果随新的人工确认继续更新；“自上次报告以来”显示变化。
- **一次性研究**：用户完成一轮收集和确认后生成报告，作为该次研究的冻结结果。

报告不是“实时页面的另一个入口”，而是生成时的冻结版本。后续新增内容不会偷偷改写旧报告。

![确认新资料后成果立即更新](screenshots/output-03-result-updated.png)

### 5.4 冻结报告

报告只读取生成时已经确认的正式对象，包含当前结论、事件、主张、固定证据、来源和未知项，并可打开证据快照。

![带证据引用的冻结报告](screenshots/output-04-report-top.png)

### 5.5 窄屏使用

核心成果页和待处理页已在 390×844 视口实际检查；内容纵向排列，不依赖横向滚动完成任务。

## 6. 测试人员逐项验收

### 6.1 输入验收

- [ ] 只填专题名称也能得到可编辑的核心问题建议。
- [ ] 关键词、网页、粘贴文本和文件可在一个窗口同时提交。
- [ ] 用户不需要选择语言或首批处理条数。
- [ ] 点击创建后专题先保存，后台处理不会阻塞窗口。
- [ ] 一条资料失败不影响其他资料进入专题。

### 6.2 处理验收

- [ ] “待处理”能区分需要确认、失败和后台处理中。
- [ ] 失败项显示原因、影响以及重试或删除动作。
- [ ] 待确认项先显示固定原文，再显示候选摘要。
- [ ] 普通用户只面对采用、修改后采用、不采用三个决定。
- [ ] 第一次点采用只出现影响预览，不写入正式成果。
- [ ] 确认采用后能打开正式事件，处理数量同步减少。
- [ ] 不采用后正式成果数量不增加。

### 6.3 成果验收

- [ ] 专题默认打开成果页，而不是工程对象列表。
- [ ] 当前结论、变化、关键发现、时间线、未知项和报告入口可见。
- [ ] 未确认候选不会出现在成果和报告中。
- [ ] 展开主张能够看到精确证据、来源和快照入口。
- [ ] 确认一条新资料后，成果数量和“自上次报告以来”同步变化。
- [ ] 新报告只包含已确认内容，并说明它是冻结版本。
- [ ] 桌面端和 390×844 窄屏都能完成核心流程。

## 8. 当前边界

- 当前成果页是“已确认结果”的用户入口，不代替完整的高级事件档案。
- 自动多语言查询扩展、完整中文归一、来源推荐包和每日报告仍是后续工作，不能当作现成功能宣传。
- 当前报告是 HTML 冻结报告；PDF/Word 自动导出尚未进入本轮功能范围。
- 公网服务必须继续经过认证网关；文档和前端不得保存 API Key 或账号密码。
- 当前性能指标是交付要求，尚未完成的 30–50 个真实来源和 72 小时连续运行必须单独验收。
