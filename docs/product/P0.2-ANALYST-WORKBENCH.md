# P0.2 分析员工作台

状态：待合并验收

日期：2026-08-27

## 目标

P0.2 不扩张底层数据范围，集中解决 P0 页面“技术闭环存在，分析员操作闭环偏弱”的问题。它把事件、主张、证据、来源和研判组织成一条可演示、可理解、可继续开发的工作流。

## 典型操作链

```text
打开专题
→ 查看地图、时间线和事件流
→ 按重要性、语言或争议状态收敛事件
→ 打开事件档案
→ 查看实体、当前研判和信息缺口
→ 切换到主张与证据
→ 打开原文快照核验
→ 查看来源资料和转载折叠
→ 生成本事件证据简报
```

新资料进入路径：

```text
导入公开网页或 RSS
→ 校验公共地址与重定向
→ 提取正文并生成哈希
→ 记录来源和重复族
→ 进入资料库
→ 后续由采集箱归并到事件
```

## 本轮变化

### 专题层

- 新增专题指挥栏、模式、时间范围、更新时间和系统状态。
- 核心指标由文字徽标升级为独立指标卡。
- 页面明确标记 P0.2 和确定性降级状态。

### 事件层

- 地理态势、时间线、事件流保持同一选择状态。
- 新增关键词、重要性、语言和争议状态组合筛选。
- 事件卡片显示重要性、文档数、独立来源数、主张数和争议状态。

### 档案层

- 使用侧边抽屉承载完整事件档案。
- 概览页显示实体、研判框架、信息缺口和证伪条件。
- 主张证据页显示主张状态、置信度、证据立场、证据强度和快照入口。
- 来源资料页显示来源层级、独立来源组、语言、时间、正文哈希和重复族标识。

### 操作层

- 当前事件可以直接生成 HTML 证据简报。
- 可以复制事件摘要。
- 可以导入公开网页或 RSS。
- 支持 Ctrl K 聚焦搜索、Escape 关闭抽屉或导入窗口。
- 页面增加加载、空状态、错误状态和操作反馈。

### 工程层

- 验收测试加入 P0.2 页面结构、报告可访问性和采集入口检查。
- 测试数据库和报告目录使用临时路径，减少不同机器之间的状态污染。
- 保留 Python 编译检查和前端 JavaScript 语法检查。

## 当前保留边界

P0.2 的导入资料已经真实进入数据库，但还没有正式的“待归并采集箱”。导入成功后，资料等待后续人工或模型归并到事件。这个缺口被明确保留，避免为了页面完整感伪造自动归并能力。

P0.2 的地图仍属于 World Monitor 风格的轻量兼容壳。它证明地图优先的产品组织方式，尚未引入完整 World Monitor 上游代码和图层体系。

P0.2 使用人工整理的公开专题快照，不能代替真实网页证据归档。

## 验收条件

1. 后端启动后首页无控制台语法错误。
2. 8 个事件、48 篇文档、24 条主张和 56 条证据正常加载。
3. 地图、时间线和事件流选择同一事件。
4. 四类筛选可组合使用并支持一键清除。
5. 事件抽屉三个标签页均可访问。
6. 证据快照保留事件返回参数。
7. 当前事件报告能够生成并在浏览器访问。
8. 公开网页和 RSS 导入入口能返回明确成功或错误状态。
9. 窄屏布局无关键按钮丢失。
10. `./scripts/test-p0.sh` 全部通过。
