# PLDR

[![CI](https://github.com/veniai/PLDR/actions/workflows/ci.yml/badge.svg)](https://github.com/veniai/PLDR/actions/workflows/ci.yml)

PLDR 是一个面向开源情报工作的证据优先工作台。它借鉴 Palantir 的对象、关系和受控 AI 思路，但不照搬通用企业本体：PLDR 以“来源—文档—快照—主张—证据—研判”为核心链路，让每项分析结论都能回到材料、版本和原文片段。

产品定位、阶段顺序和验收要求分别见：

- `docs/product/PRODUCT-VISION.md`：为什么做以及哪些原则不能破坏；
- `docs/product/FUNCTIONAL-PERFORMANCE-REQUIREMENTS.md`：用户功能、性能指标、当前状态和验收口径；
- `docs/product/ROADMAP.md`：P0 至 P4 的阶段顺序和退出条件；
- `docs/research/REFERENCE-PROJECTS.md`：参考项目对应的用户问题、要求编号和使用边界。

当前仓库已完成 **P1 外部关键词发现**，并实现 **P1 可靠采集的固定网页与 RSS 纵向切片**。工作台以“专题”而不是一组互不相干的页面为操作单位：确定网页、RSS、后续 API 来源、粘贴文本、本地文件和关键词搜索属于并列输入；关键词搜索用于发现尚不知道 URL 的材料，不替代已知来源采集，也不会绕过人工确认。内置专题用于演示从并行输入、候选隔离、人工审核、事件聚合、主张证据、结构化研判到证据简报生成的完整闭环。完整 P1 还必须把这些能力放入至少一个冻结范围和来源的真实专题包，并证明分析员能够回答“今天出现了什么、依据是什么、还缺什么”：

```text
确定网页 ───────────────────────────────┐
粘贴文本 / 本地文件 / 手动 RSS ────────┤
外部关键词 → 真实检索结果 → 专题相关性初筛 → 人工选择或启动时自动提交明确相关原页 ├→ 专题待处理队列
后续 API 可靠来源（尚未实现）───────────┘
固定网页 → 持久队列 → 首次/未变/变化/失败 → 版本 Diff ↗
RSS/Atom → 条目指纹去重 → 新条目/重复/无效 ↗
        → 异步候选生成 → 人工语义审核与确认
        → 正式文档与快照 → 事件、实体、主张与证据
        → 分项研判与证据缺口 → 带引用的 HTML 简报
```

P0 当前内置 16 个来源、48 篇文档、8 个事件、24 条主张和 56 条证据。所有演示证据在写入时都执行正文精确子串校验。文档数量与独立来源组数量分别计算，机器主张、人工复核和结构化研判分别保存。

## P0.2 工作台

P0.2 将原来的技术样机收敛成面向分析员的操作界面：

- 专题指挥栏显示专题模式、时间范围、更新时间和核心指标。
- 地理态势、时间线、事件流和结构化研判保持联动。
- 事件档案采用侧边抽屉，分为概览、主张与证据、来源资料三个视图。
- 主张明确显示状态、置信度、支持证据、冲突证据和原文快照入口。
- 来源资料显示可靠性分层、独立来源组、正文哈希和转载折叠标识。
- 当前事件可以直接生成 HTML 证据简报。
- 可以导入公开网页或 RSS，系统保存规范化 URL、来源、抓取时间和内容哈希。
- 支持关键词、重要性、语言、争议状态筛选，并适配桌面和小屏浏览器。

## P0.3 待处理采集箱

- 公共网页、粘贴文本、TXT/Markdown/HTML/PDF 本地文件和手动 RSS 条目统一进入持久化采集箱。
- 条目保留输入类型、状态、错误、来源说明、时间、原始/提取快照和材料指纹；私网地址、空文本、损坏或超限文件安全失败且不进入正式区。
- 模型输出只写入候选 Event、Entity、Claim、Evidence 及关系；无模型时使用确定性引用降级，未知标题、时间和出处保持未知。
- 候选 Evidence 必须精确命中完整提取快照；分析员可预览并执行新建、合并、修改后确认、驳回或撤销。
- 确认事务一次性生成或关联正式 Source、Document、Snapshot、Event、Entity、Claim、Evidence，保留机器候选、人工差异、处置记录和最终对象 ID；重复确认具有幂等结果。

## P1 外部关键词发现

- 工作台在具体专题内提供独立于“筛选已入档事件”的公开资料搜索入口，支持新闻和一般公开网页范围；查询历史与结果保存在该专题，关闭窗口后可以重新打开。
- 默认通过 Brave Search API REST v1 接入真实检索；也可配置运营方自管的 SearXNG JSON 实例。组件版本、许可证和部署边界见 `docs/product/P1-EXTERNAL-KEYWORD-DISCOVERY.md`。
- 每次查询可请求 10 或 20 条并继续下一页；Brave 每页最多返回所选数量，SearXNG 的实际页大小由运营方实例决定，PLDR 会在单查询 100 条上限内保留其完整返回页。跨页去重后支持全选本页、全选已加载结果或取消选择，单批最多选择 100 条。上游未提供总数时只显示“已加载”和“还能否继续”，不伪报总结果数。
- 每项结果显示原始 URL、站点、检索渠道、标题和可获得的摘要或时间；空结果和后端失败保持真实状态，不用演示数据伪装。失败信息按阶段说明原因、影响、是否值得重试、下一步动作和追踪 ID。
- 搜索结果先按专题词对标题和摘要做可解释初筛；创建专题时只有“与专题相关”的结果自动进入处理，相关性存疑或可能无关的结果仍保留在“发现资料”，用户可手动选择。进入处理后异步逐条抓取原始页面；一项失败不会让整批失去进度。查询运行、渠道、结果、关键词和最终材料的追踪关系持久保留。
- 检索渠道不是正式 Source，搜索标题、摘要和排名不是 Evidence；成功抓取后仍必须经过 AI 候选、证据精确定位和人工确认。
- 结果 URL 沿用公共地址、DNS 解析、每一跳重定向和 SSRF 防护并默认拒绝不安全地址。暂时性超时、限流等错误可重试；DNS/SSRF 策略拒绝不会提供无意义的原样重试，需先更换公开地址或修正部署网络。所有失败均不污染正式对象。重复提交同一规范化结果 URL 具有幂等行为。

## 专题审核与当前研判

- “今天”按待审核、处理中、失败和已确认事件组织注意力队列，不再把结果当作一次性资讯流。
- “当前研判”分别展示来源可靠性、独立来源印证、证据完整性和明确标记的人工研判；每项可展开查看依据。没有数据时保持“未知”，不把机器候选置信度合成为看似精确的总分。
- 审核默认只显示当前专题的合并目标；跨专题复用必须显式打开并在确认前展示目标归属。
- 确认前显示 Source、Document、Snapshot、Event、Claim、Evidence 与关系/动作的语义预览；确认后返回正式事件档案，并可继续下一条待审任务。
- 正式专题报告只读取已确认对象；搜索结果、抓取失败和未确认 AI 候选不会进入正式事件、指标或报告。

## P1 固定网页与 RSS 可靠采集切片

- “来源监测”独立于正式 `Source`：分析员可以添加固定公共网页或 RSS/Atom、设置周期、立即检查、暂停/恢复和重试失败运行。
- 手动、到期和重试先写入持久化 `CollectionRun`，再由单 collector 领取；排队、运行、结果、错误、耗时和恢复租约均可追踪。
- 首次正文形成 V1；正文哈希未变只记运行，不重复产生待审项；正文变化形成下一个不可变待审版本，并提供确定性 Vn/Vn-1 Diff。
- 抓取成功与 AI 候选生成分开显示。版本仍走 P0.3 的预览、新建、合并、修改候选后新建、驳回和确认流程。
- 同一 URL 的新确认版本复用一个正式 `Document`，新增不可变 `Snapshot`；旧、新 `Evidence` 分别固定自己的快照，报告引用不会随文档最新版本漂移。
- RSS/Atom 按目标内 GUID/URL 加内容指纹去重；新条目保存来源提供的标题与摘要快照并进入 P0.3 审核，重复项只保留运行计数，私网或无有效公共链接的条目计入无效。
- 当前只支持无需登录的固定 HTTP(S) 网页、RSS/Atom 条目摘要和单 worker；完整范围、运行方法与验收见 `docs/product/P1-RELIABLE-COLLECTION-SLICE.md`。

## 直接运行

需要 Python 3.11 及以上：

```bash
./scripts/setup-p0.sh
./scripts/test-p0.sh
./scripts/run-p0.sh
```

可靠采集需要另一个终端运行持久队列 worker：

```bash
./scripts/run-collector.sh
```

浏览器打开：

```text
http://127.0.0.1:8765
```

当前环境已经安装依赖时，可以跳过 `setup-p0.sh`。

外部关键词发现需要一个真实检索后端。默认适配 Brave Search API，运行前配置：

```env
PLDR_SEARCH_PROVIDER=brave
PLDR_SEARCH_API_KEY=你的密钥
```

也可以连接自行部署并启用 JSON 输出的 SearXNG：

```env
PLDR_SEARCH_PROVIDER=searxng
PLDR_SEARCH_BASE_URL=https://search.example.org
```

未配置后端时，搜索界面和 API 会明确失败；其他四类输入和采集审核闭环不受影响。

也可以使用 Docker；Compose 会同时启动 API 和一个 collector：

```bash
docker compose up --build
```

## 数据边界

P0 内置专题用于验证产品和工程闭环。文档正文是人工整理的公开事实改写摘要，不应被当成原始网页的永久替代品。进入业务试点前，需要重新抓取真实原始网页，保存原始内容或合规快照，并逐条核验事实与授权边界。

网页导入只允许公共 HTTP/HTTPS 地址。系统阻止 localhost、私网、链路本地和保留地址，并校验每一个 HTTP 重定向跳转。离线测试可以直接提交 HTML 或 RSS XML，不产生外部网络请求。

外部搜索结果只保存为专题内的查询线索和选择追踪。搜索标题、摘要、排名、相对时间和检索渠道不是事实、Source 或 Evidence。只有用户选择后成功抓取的原始页面快照，才可能进入候选证据与人工确认流程。上游结果总数未知时，PLDR 也保持未知。

固定网页和 RSS 配置和采集运行也不是正式 Source 或 Evidence。固定网页内容只在首次或正文变化时进入待审箱；RSS 保存的是来源提供的条目标题与摘要快照，不冒充已抓取原文。只有人工确认的具体材料才成为正式 Snapshot，证据始终固定到该版本。

## 模型

模型属于可替换配置。没有模型 API 时，P0 仍能完整运行。

```env
LLM_API_KEY=
LLM_BASE_URL=
LLM_MODEL_NAME=
LLM_TIMEOUT_SECONDS=60
LLM_MAX_CONCURRENCY=1
LLM_EXTRACTION_MAX_TOKENS=1400
LLM_REASONING_EFFORT=
PLDR_MODEL_AUTO_RETRY_ATTEMPTS=3
PLDR_MODEL_AUTO_RETRY_BASE_SECONDS=60
PLDR_MODEL_AUTO_RETRY_MAX_SECONDS=900
```

业务层只调用统一任务：标题规范化、事件摘要、实体地点抽取、主张证据抽取、采集箱候选抽取和报告草稿。所有候选仍需人工确认。网页正文使用 Trafilatura 清理；可选 Jina Reader 只在安全直抓失败或正文质量不足后启用。代理网络可配置 HTTPS DoH 独立验证公开目标后再走 Reader，不能通过 Reader 绕过非公网地址保护。模型超时或临时失败时保留原文、按退避时间自动重新排队，默认自动重试 3 次；重试期间不要求用户操作，也不生成容易误解的伪成功草稿。多次重试仍失败后才进入需要处理，并允许用户只重试分析。

## 当前边界

P1 关键词发现和固定网页/RSS 可靠采集切片已经形成可运行闭环，但**完整 P1 尚未退出**。首个真实专题包及其“今天”输出、需要登录或携带会话的受控浏览器来源、RSS 条目原文追抓、30–50 个真实来源、连续 72 小时、安全与性能基准、PostgreSQL/PostGIS、模型调用成本与最终验收报告仍待完成；任何未确认候选都不会进入正式档案或报告。详见 `STATUS.md`、`docs/product/FUNCTIONAL-PERFORMANCE-REQUIREMENTS.md`、`docs/product/P1-EXTERNAL-KEYWORD-DISCOVERY.md`、`docs/product/P1-RELIABLE-COLLECTION-SLICE.md` 与 `docs/product/ROADMAP.md`。
