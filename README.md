# PLDR

[![CI](https://github.com/veniai/PLDR/actions/workflows/ci.yml/badge.svg)](https://github.com/veniai/PLDR/actions/workflows/ci.yml)

PLDR 是一个面向开源情报工作的证据优先工作台。它借鉴 Palantir 的对象、关系和受控 AI 思路，但不照搬通用企业本体：PLDR 以“来源—文档—快照—主张—证据—研判”为核心链路，让每项分析结论都能回到材料、版本和原文片段。

当前仓库已完成 **P1 第一个纵向切片：外部关键词发现**。内置专题用于演示从关键词检索、选择原始页面、候选隔离、人工审核、事件聚合、主张证据、结构化研判到证据简报生成的完整闭环：

```text
外部关键词 → 真实检索结果 → 用户选择原始页面 → 待处理采集箱
        → 机器候选 → 人工确认 → 正式文档与快照
        → 事件聚合 → 实体与主张 → 支持/冲突证据 → 来源独立性
        → 结构化研判 → 带引用的 HTML 简报
```

P0 当前内置 16 个来源、48 篇文档、8 个事件、24 条主张和 56 条证据。所有演示证据在写入时都执行正文精确子串校验。文档数量与独立来源组数量分别计算，机器主张、人工复核和结构化研判分别保存。

## P0.2 工作台

P0.2 将原来的技术样机收敛成面向分析员的操作界面：

- 专题指挥栏显示专题模式、时间范围、更新时间和核心指标。
- 地理态势、时间线、事件流和结构化研判保持联动。
- 事件档案采用侧边抽屉，分为概览、主张与证据、来源资料三个视图。
- 主张明确显示状态、置信度、支持证据、冲突证据和原文快照入口。
- 来源资料显示可靠性分层、独立来源组、正文哈希和转载折叠标识。
- 当前事件可以直接生成 HTML 证据简报。
- 可以导入公开网页或 RSS，系统保存规范化 URL、来源、抓取时间和内容哈希。
- 支持关键词、重要性、语言、争议状态筛选，并适配桌面和小屏浏览器。

## P0.3 待处理采集箱

- 公共网页、粘贴文本、TXT/Markdown/HTML/PDF 本地文件和手动 RSS 条目统一进入持久化采集箱。
- 条目保留输入类型、状态、错误、来源说明、时间、原始/提取快照和材料指纹；私网地址、空文本、损坏或超限文件安全失败且不进入正式区。
- 模型输出只写入候选 Event、Entity、Claim、Evidence 及关系；无模型时使用确定性引用降级，未知标题、时间和出处保持未知。
- 候选 Evidence 必须精确命中完整提取快照；分析员可预览并执行新建、合并、修改后确认、驳回或撤销。
- 确认事务一次性生成或关联正式 Source、Document、Snapshot、Event、Entity、Claim、Evidence，保留机器候选、人工差异、处置记录和最终对象 ID；重复确认具有幂等结果。

## P1 外部关键词发现

- 工作台提供独立于“筛选已入档事件”的公开资料搜索入口，支持新闻和一般公开网页范围。
- 默认通过 Brave Search API REST v1 接入真实检索；也可配置运营方自管的 SearXNG JSON 实例。组件版本、许可证和部署边界见 `docs/product/P1-EXTERNAL-KEYWORD-DISCOVERY.md`。
- 每项结果显示原始 URL、站点、检索渠道、标题和可获得的摘要或时间；空结果和后端失败保持真实状态，不用演示数据伪装。
- 只有用户勾选的结果会抓取原始页面并进入 P0.3 采集箱；查询运行、渠道、结果、关键词和最终材料的追踪关系持久保留。
- 检索渠道不是正式 Source，搜索标题、摘要和排名不是 Evidence；成功抓取后仍必须经过 AI 候选、证据精确定位和人工确认。
- 结果 URL 沿用公共地址、每一跳重定向和 SSRF 防护；失败可见、可重试且不污染正式对象。重复提交同一规范化结果 URL 具有幂等行为。

## 直接运行

需要 Python 3.11 及以上：

```bash
./scripts/setup-p0.sh
./scripts/test-p0.sh
./scripts/run-p0.sh
```

浏览器打开：

```text
http://127.0.0.1:8765
```

当前环境已经安装依赖时，可以跳过 `setup-p0.sh`。

外部关键词发现需要一个真实检索后端。默认适配 Brave Search API，运行前配置：

```env
PLDR_SEARCH_PROVIDER=brave
PLDR_SEARCH_API_KEY=你的密钥
```

也可以连接自行部署并启用 JSON 输出的 SearXNG：

```env
PLDR_SEARCH_PROVIDER=searxng
PLDR_SEARCH_BASE_URL=https://search.example.org
```

未配置后端时，搜索界面和 API 会明确失败；其他四类输入和采集审核闭环不受影响。

也可以使用 Docker：

```bash
docker compose up --build
```

## 数据边界

P0 内置专题用于验证产品和工程闭环。文档正文是人工整理的公开事实改写摘要，不应被当成原始网页的永久替代品。进入业务试点前，需要重新抓取真实原始网页，保存原始内容或合规快照，并逐条核验事实与授权边界。

网页导入只允许公共 HTTP/HTTPS 地址。系统阻止 localhost、私网、链路本地和保留地址，并校验每一个 HTTP 重定向跳转。离线测试可以直接提交 HTML 或 RSS XML，不产生外部网络请求。

外部搜索结果只保存为查询线索和选择追踪。搜索标题、摘要、排名、相对时间和检索渠道不是事实、Source 或 Evidence。只有用户选择后成功抓取的原始页面快照，才可能进入候选证据与人工确认流程。

## 模型

模型属于可替换配置。没有模型 API 时，P0 仍能完整运行。

```env
LLM_API_KEY=
LLM_BASE_URL=
LLM_MODEL_NAME=
LLM_TIMEOUT_SECONDS=60
```

业务层只调用统一任务：标题规范化、事件摘要、实体地点抽取、主张证据抽取、采集箱候选抽取和报告草稿。所有候选仍需人工确认。
